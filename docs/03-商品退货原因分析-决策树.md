# 项目三：商品退货原因分析（决策树）

> **配属模型**：决策树分类 `DecisionTreeClassifier`
> **技术栈**：Python / Pandas / scikit-learn / FastAPI / Vue 3 + ECharts
> **大数据链路**：HDFS 与 HBase 必接入；Hive 可选
> **难度**：进阶，重点体现可解释性

## 一、项目简介

根据电商订单数据和退货记录，构造订单是否退货的标签，回答两个问题：

1. 什么样的订单更容易退货？
2. 如何把模型结果转成运营人员可以读懂的判断规则？

决策树的优势是能够把分类过程表示成一组条件分支，例如：

```text
如果 category = 服饰
且 is_promotion = 1
且 price <= 某个阈值
那么该订单的退货风险较高
```

以上规则只是表达方式示例，最终阈值和结论必须以实际训练结果为准。

## 二、业务边界

### 1. 预测时点

预测发生在订单提交后、退货发生前。模型只能使用下单时可获得的信息：

```text
category
price
is_promotion
season
freight
```

不得将以下退货发生后的字段作为模型特征：

```text
return_reason
return_date
refund_amount
return_status
客服、仓储和售后处理结果
```

### 2. 标签定义

以订单表为主表，按照 `order_id` 关联退货表：

```text
returned = 1：订单在退货观察窗口内存在有效退货记录
returned = 0：观察窗口结束前没有有效退货记录
```

同一个订单的多条退货记录只能生成一个订单级样本。观察窗口、有效退货状态和去重规则必须写入清洗报告。

## 三、建模路线图

```text
① 采集订单/退货表
        ↓
② 清洗、去重、关联并生成 returned
        ↓
③ 类别编码与特征检查
        ↓
④ 分层划分训练集/测试集
        ↓
⑤ 训练决策树并限制复杂度
        ↓
⑥ 评估、特征重要性、混淆矩阵和规则导出
        ↓
⑦ FastAPI 提供预测与分析数据
        ↓
⑧ Vue 3 + ECharts 展示
```

## 四、数据准备

### 1. 训练表

训练表 `return_model.csv` 至少包含：

| 列 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `order_id` | string | 订单唯一标识，不进模型 | `order_000001` |
| `category` | 类别 | 商品类目 | 服饰 |
| `price` | 数值 | 商品成交单价，元 | 299 |
| `is_promotion` | 0/1 | 是否促销 | 1 |
| `season` | 类别 | 下单季节 | 夏 |
| `freight` | 数值 | 运费，元 | 0 |
| `returned` | 0/1 | 是否退货标签 | 1 |

订单和退货数据的完整定义见 [`data-dictionary.md`](data-dictionary.md)，清洗流程见 [`data-collection.md`](data-collection.md)。

### 2. 数据质量

建模前必须检查：

```python
df.info()
df.isna().sum()
df.duplicated(subset=["order_id"]).sum()
df["returned"].value_counts(normalize=True)
```

如果退货样本比例明显较低，不能只看准确率，应重点查看退货类的召回率、F1 和混淆矩阵。

## 五、特征工程

推荐使用 `ColumnTransformer` 和 `OneHotEncoder`，避免手工维护类别编码顺序：

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

categorical_features = ["category", "season"]
numeric_features = ["price", "is_promotion", "freight"]

preprocessor = ColumnTransformer(
    transformers=[
        (
            "categorical",
            OneHotEncoder(handle_unknown="ignore"),
            categorical_features,
        ),
        ("numeric", "passthrough", numeric_features),
    ]
)
```

注意事项：

1. 预处理器只能在训练集上拟合；
2. 测试集只能调用 `transform`；
3. 训练和推理必须加载同一份 Pipeline；
4. 不把 `order_id` 当作数值特征；
5. 不把退货原因、退款金额等结果字段放入 `X`。

## 六、模型训练与评估

### 1. 基础实现

```python
from sklearn.metrics import (
    accuracy_score,
    classification_report,
    confusion_matrix,
    f1_score,
    precision_score,
    recall_score,
)
from sklearn.model_selection import train_test_split
from sklearn.pipeline import Pipeline
from sklearn.tree import DecisionTreeClassifier

feature_cols = [
    "category",
    "price",
    "is_promotion",
    "season",
    "freight",
]

X = df[feature_cols]
y = df["returned"]

X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.3,
    random_state=42,
    stratify=y,
)

model = Pipeline(
    steps=[
        ("preprocess", preprocessor),
        (
            "classifier",
            DecisionTreeClassifier(
                max_depth=4,
                min_samples_leaf=10,
                class_weight=None,
                random_state=42,
            ),
        ),
    ]
)

model.fit(X_train, y_train)
y_pred = model.predict(X_test)

metrics = {
    "accuracy": accuracy_score(y_test, y_pred),
    "precision": precision_score(y_test, y_pred, zero_division=0),
    "recall": recall_score(y_test, y_pred, zero_division=0),
    "f1": f1_score(y_test, y_pred, zero_division=0),
    "confusion_matrix": confusion_matrix(y_test, y_pred).tolist(),
}

print(classification_report(y_test, y_pred, zero_division=0))
print(metrics)
```

`class_weight="balanced"` 可以作为对照实验配置，但是否启用应通过验证集或交叉验证比较后决定，不能默认认为一定更好。

### 2. 防止过拟合

重点观察：

- `max_depth`：限制树的最大深度；
- `min_samples_leaf`：限制叶节点最小样本量；
- `min_samples_split`：限制继续分裂所需的样本量；
- 训练集和测试集指标差距；
- 测试集混淆矩阵和少数类召回率。

建议记录不同参数组合的结果，选择兼顾性能与可解释性的模型，而不是只追求训练集最高准确率。

## 七、特征重要性与规则导出

### 1. 特征重要性

One-Hot 后的特征名称应从预处理器中取得，再与分类器的 `feature_importances_` 对齐：

```python
feature_names = model.named_steps["preprocess"].get_feature_names_out()
importances = model.named_steps["classifier"].feature_importances_

feature_importance = sorted(
    zip(feature_names, importances),
    key=lambda item: item[1],
    reverse=True,
)
```

前端展示时建议同时显示：

- 特征名称；
- 重要性；
- 重要性排序；
- 训练样本范围；
- “重要性不等于因果关系”的说明。

### 2. 文本规则

```python
from sklearn.tree import export_text

tree = model.named_steps["classifier"]
rules = export_text(tree, feature_names=list(feature_names))
print(rules)
```

`export_text()` 只用于调试和答辩文本，不作为 API 的最终规则格式。前端结构化规则必须遍历树节点，并将 One-Hot 特征还原为原始字段和值：

- `category_服饰 <= 0.5` 应还原为“不属于服饰”；
- `category_服饰 > 0.5` 应还原为“category = 服饰”；
- `price`、`freight` 和 `is_promotion` 保留原始字段和单位；
- 每条规则必须带叶节点样本数和退货概率。

结构化规则输出：

```json
{
  "rule_id": "leaf-3",
  "conditions": ["price <= 120.50", "is_promotion = 1"],
  "predicted_returned": 1,
  "return_probability": 0.71,
  "sample_count": 86
}
```

规则中的类别编码要转换回可读的原始类别，不能直接把 `x[12]` 之类的内部索引展示给用户。

模型训练数据从 HDFS 读取，模型产物写回 HDFS；模型版本和当前生效指针登记到 HBase，FastAPI 只能加载 HBase 注册表中状态为 `ready` 的模型。

## 九、项目输出与答辩亮点

1. 用一棵限制深度的决策树说明模型为什么可解释；
2. 用训练集和测试集指标差距解释过拟合控制；
3. 用退货类召回率和 F1 说明类别不均衡下不能只看准确率；
4. 将模型叶节点规则转成业务人员可以阅读的条件；
5. 明确说明退货原因等事后字段没有进入预测特征，避免标签泄漏。

## 十、风险和限制

- 决策树的特征重要性只能说明模型使用程度，不代表真实因果关系；
- 退货标签依赖观察窗口，窗口变化会改变训练结果；
- 类目、促销和季节的定义变化会影响模型版本兼容性；
- 预测结果用于风险提示，不应单独作为拒绝售后或处罚用户的依据；
- 真实实验结果必须来自实际数据，文档中的示例数值不能替代实验结果。

## 十一、验收标准

- [ ] 训练表为订单级，一条订单只有一行。
- [ ] `returned` 标签可由退货表按观察窗口重建。
- [ ] 训练和推理使用同一个预处理 Pipeline。
- [ ] 训练过程固定随机种子并记录参数。
- [ ] 输出准确率、精确率、召回率、F1 和混淆矩阵。
- [ ] 输出特征重要性和可读规则。
- [ ] 测试集没有被用于拟合预处理器。
- [ ] 退货发生后的字段未进入模型特征。
