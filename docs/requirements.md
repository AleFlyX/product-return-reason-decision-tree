# 项目需求说明

## 一、项目目标

构建一个基于订单与退货数据的商品退货分析系统。系统应能清洗并关联订单、退货数据，训练决策树分类模型，预测订单是否退货，并将退货率、影响因素和可解释规则展示给项目成员、展示用户和验收人员。

## 二、用户角色

| 角色 | 使用内容 |
| --- | --- |
| 项目成员 | 导入数据、执行清洗、训练模型、检查指标 |
| 运营/展示用户 | 查看退货概览、类目分析和单笔订单预测 |
| 教师/验收人员 | 检查数据链路、模型解释性、接口和演示流程 |

## 三、业务定义

### 1. 分析对象

分析对象是一条订单级样本，而不是一条退货明细。订单表提供预测时点的信息，退货表用于生成订单是否退货的标签。

### 2. 标签与观察窗口

字段 `returned` 的定义：

- `1`：订单在约定退货观察窗口内存在有效退货记录；
- `0`：观察窗口结束时没有有效退货记录。

最终观察窗口由项目成员结合数据源确定，并写入清洗报告。不能使用观察窗口结束后才产生的信息作为模型输入。

## 四、功能需求

### 数据处理

- 支持订单 CSV 和退货 CSV 输入。
- 统一字段名称、字符编码、日期格式和数值单位。
- 对订单和退货记录去重。
- 记录缺失值、异常值、无主退货记录和无法关联订单。
- 按 `order_id` 生成订单级 `returned` 标签。
- 输出清洗报告和可供训练使用的 `return_model.csv`。

### 特征工程

- 对 `category`、`season`、`is_promotion` 完成类别编码。
- 对 `price`、`freight` 做数值类型转换和范围校验。
- 使用分层方式划分训练集和测试集。
- 训练和推理使用同一套预处理 Pipeline。
- 显式检查退货原因、退款金额等潜在标签泄漏字段。

### 模型

- 使用 `DecisionTreeClassifier` 完成二分类。
- 固定随机种子，记录训练数据版本和模型参数。
- 输出准确率、精确率、召回率、F1、混淆矩阵和特征重要性。
- 保存可加载的模型 Pipeline、指标 JSON、特征重要性 JSON 和规则 JSON。
- 通过 `max_depth`、`min_samples_leaf` 等参数控制复杂度。

### 后端

- 提供健康检查、数据概览、订单分页、退货预测、模型指标、特征重要性和规则接口。
- 使用 Pydantic 校验预测输入。
- 使用统一 JSON 错误格式。
- 自动生成 OpenAPI 文档。

### 前端

- 使用 Vue 3 + Vite。
- 提供概览、退货分析、订单预测和模型解释页面。
- 使用 ECharts 展示退货率、类目对比、特征重要性和混淆矩阵。
- 对加载中、无数据、接口失败和模型未加载状态进行处理。

## 五、非功能需求

- 可复现：相同数据、代码和随机种子应得到相同训练划分和可比指标。
- 可解释：每个指标标明数据范围、样本量和计算口径；规则可以追溯到树节点。
- 可维护：采集、清洗、特征工程、模型、后端和前端模块边界清晰。
- 可测试：清洗、标签构造、模型评估和 API 至少具备基础测试。
- 可部署：后端可以用 Uvicorn 启动，前端可以用 Vite 构建。
- 可降级：没有 HDFS/Hive/HBase 时，核心链路可使用本地 CSV。
- 数据安全：不采集不必要的个人敏感信息；对订单编号做脱敏或使用内部测试编号。

## 六、验收用例

| 编号 | 用例 | 期望结果 |
| --- | --- | --- |
| U01 | 启动后端并访问健康检查 | 返回 `status=ok` 和模型加载状态 |
| U02 | 请求退货概览 | 返回订单数、退货数和退货率 |
| U03 | 请求类目退货分析 | 返回类目、样本量和退货率 |
| U04 | 提交合法订单特征 | 返回预测类别、退货概率和模型版本 |
| U05 | 提交缺失或非法参数 | 返回 4xx 和字段错误 |
| U06 | 打开模型分析页面 | 展示模型指标和特征重要性 |
| U07 | 请求决策树规则 | 返回可读条件和叶节点样本信息 |
| U08 | 后端不可用时打开前端 | 显示错误状态，不出现空白页面 |
| U09 | 检查训练特征 | 不包含退货原因、退款金额等标签泄漏字段 |
